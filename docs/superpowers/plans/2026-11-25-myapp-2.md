# myApp 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (execuție nativă, un singur agent, la cererea utilizatorului). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconstruirea myApp ca Supervisor Control Center: UI nou, model de date Plan/Execuție/Master, module integrate.

**Architecture:** Domeniu pur în `js/domain/*` (testat cu `node --test`), nucleu în `js/core/*` (timp, numere, persistență, migrare), UI în `js/ui/*` și `js/views/*`, randat cu un helper `h()` sigur (doar `textContent`). Router pe hash, un singur document IndexedDB `v2`.

**Tech Stack:** HTML, CSS (tokens), ES modules, IndexedDB, Service Worker, Playwright (doar verificare, în afara repository-ului).

**Spec:** `docs/superpowers/specs/2026-11-25-myapp-2-design.md`

## Global Constraints

- Fără dependențe la rulare, fără CDN, fără servicii plătite, fără sudo.
- Date reale interzise în repository. Demo = sintetic și marcat.
- Lipsă ≠ 0 ≠ 100 %. Zero confirmat este distinct.
- Fiecare fișier nou intră în `sw.js`, iar versiunea cache-ului crește.
- Calificare exact 1–4, „neevaluat” separat.
- Fără commit / push / deploy fără acordul utilizatorului.

## Review Focus

1. Schimb de noapte 22:00–06:00: intervalele, data de lucru și raportarea după miezul nopții.
2. Oprire care traversează mai multe ore și două incidente pe aceeași oprire: minutele nu se dublează.
3. Corectarea orei de pornire după raportare: indicatorii se recalculează, iar istoricul corecției rămâne.
4. Restaurarea unui backup malițios (`__proto__`, tipuri greșite, > 32 MB): se respinge fără a corupe documentul curent.
5. Persoană absentă dar alocată / alocată pe două linii simultan: apare conflict vizibil, nu blocare tăcută.

## Tasks (execuție în ordinea dependențelor)

### Task 1: Nucleu (`js/core/time.js`, `num.js`, `h.js`, `store.js`, `migrate.js`, `seed.js`, `csv.js`)
- Test: `tests/core.test.mjs`: `shiftWindow` noapte, `slotsOf` 8 intervale, `overlapMin`, `nn` (lipsă/zero/invalid), `sanitize` elimină `__proto__`, `migrateV4` (niveluri 1→2…, problemă deschisă → task).

### Task 2: Plan (`js/domain/plan.js`)
- `distribute(run, shift, method) -> number[]`, `planHourly(linePlan, shift)`, `confirmBaseline`, `revise`.
- Test: suma = target pentru toate metodele, exemplul 760, pauza scade minutele, cycle-time floor, ciclu lipsă → null.

### Task 3: Linii și evenimente (`js/domain/lines.js`)
- `statusAt(events, t)`, `timeline(events, window)`, `minutesByStatus`, `correctEvent`.
- Test: oprire peste 2 ore, corecție a orei, eveniment anulat, status necunoscut.

### Task 4: Raportare + OEE (`js/domain/reports.js`, `oee.js`)
- `slotState`, `cumulative`, `lineOee`, `aggregateOee`.
- Test: PN schimbat în oră, zero confirmat vs lipsă, OEE A×P×Q = forma simplă la PN-uri eterogene, ICT lipsă → P null.

### Task 5: Incidente, sarcini, rutină (`incidents.js`, `tasks.js`, `routine.js`)
- Mașini de stare cu tranziții permise, MTTR/MTBF cu prag de date, task restant, instanțe de rutină fără duplicate, ferestre de timp, NOK → task.

### Task 6: Oameni (`workforce.js`)
- Conflicte (absent alocat, dublă alocare, nivel insuficient, nivel 1–2 fără suport), acoperire, sugestii de redistribuire.

### Task 7: Calitate și Lean (`audits.js`, `quality.js`)
- Versionarea checklisturilor (snapshot la audit), scor 5S/6S fără N/A în numitor, reguli 8D (D4 cere cauză verificată, D6 cere rezultat), prioritate Kaizen.

### Task 8: Asistent + predare (`assistant.js`, `handover.js`)
- Reguli cu evidență și rută. Test: fără date → nicio alertă.

### Task 9: Design system + shell + toate ecranele (`css/*`, `js/ui/*`, `js/views/*`, `index.html`, `sw.js`)
- Verificare: Playwright la 360/390/430/768/1440, light/dark, două iterații de critică vizuală.

### Task 10: Verificare finală
- `node --test tests/*.mjs`, flux browser end-to-end, offline, backup/restore, review de cod și securitate, documentație, `PROGRESS.md`.
